# CKLogs 修复与验证记录

日期：2026-10-25。

本次实施延续 `cklogs-p93-p94-p95-analysis.md`，仅修改当前 platform-gateway 仓库；按后续用户指示提交并合入本地 main，不部署、不变更生产配置。

## 实施范围

- P-94：停止在收件人精确零命中后删除 Recipient 扫描宽候选。由于目前仓库没有可证明覆盖分号拼接地址的字段 mapping/规范化字段契约，无法确认时返回 unresolved，而非假报无记录。该修复消除危险宽扫；恢复所有拼接收件人的检索能力仍需数据平台配合验证。
- P-95：DATRANS 真正消费 size/from，最多取5000条原始事件，收齐后过滤聚合分页。对总数漂移、未知总数、短页、重复或不安全边界采取完整性错误，保留单页500限制。offset 查询不提供快照隔离，迟到/并发写入的影响需真实后端确认。
- P-93：增加查询阶段、预算与不含原始条件的查询诊断；加强读取与响应完整性检查。保留串行短路，不推测执行可能昂贵的候选查询，也不调大超时。修正固定“60秒”的超时说明。

## 上线前外部条件

生产 P-93 慢查询的根因和 p95<30s 尚未由本地代码验证。必须使用四例原始参数，在实际数据平台确认查询计划、字段类型、排序/回表开销后决定查询或索引优化。不要把新增审计等同于慢查询性能问题已经解决。

现网默认单次60s、整单90s、队列30s；相邻 self-service Node 默认 fetch 95s，仍存在总预算不匹配。本次不修改相邻仓库或静默压缩网关预算。若保留90s整单，上游等待至少应容纳队列30s+执行90s+余量（按5s示例为125s），并复核所有代理层；增加预算应先评估两个并发槽的占用和队列延迟。

DATRANS 多页结果不能跨不安全的时间戳边界，且不会假设后端支持 PIT、_id 排序或额外 keyword 字段。若生产经常同时间戳跨页，应补充平台支持的稳定游标/唯一排序键后扩展，而非删除完整性保护。

前端单页500常量保持正确，不应改5000；应在 self-service 后续联调中将正常聚合多页与不完整提示区分。countOnly仍为原始事件计数，与聚合明细total语义不同。
